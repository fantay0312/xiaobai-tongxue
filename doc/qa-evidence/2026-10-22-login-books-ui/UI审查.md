## 建议优先级

### P1：收敛一级导航

首页左侧有对话、工作台、阅读、教小白、AI 课堂、助理任务、科研台、记忆、资料库，底部另有成长册和设置。再叠加课程树与对话列表，用户需要先理解产品结构才能开始。

建议把高频入口固定为“学习、阅读、教小白、工作台”，其余放“更多”。课程/资料是当前学习任务的内容，记忆与成长是任务的结果，不必长期与主任务并列。先看使用数据，再决定是否调整现有名称与排列。

### P1：首页只强调一个下一步

当前同时有大问候、拜师帖、人物气泡、四块同权入口、最近记录、成长状态和输入框。第一次可以讲故事，回访时应立即看见正在学什么。

建议“继续上次学习”为唯一主操作，“上传资料”作次操作；“给小白讲/生成课堂”随当前课程出现。读过的拜师帖收为小入口，保留故事但不反复占首页高度。

### P1：空笔记本不要遮住第一次阅读

当前默认/已固定的笔记本在桌面约占三分之一宽度，在手机会覆盖几乎全部正文，刚打开的书看起来像空白页。

建议新用户默认关闭，首次创建高亮或提问后再提示打开；尊重用户明确固定的偏好。手机打开后要一直看得到“返回正文”。

### P1：输入框只保留高频决定

现在用户发送一个问题前会同时看见附件、回答方式、互动回答、资料范围、模型、思考强度、语音等设置。它们都合理，但同时展开会令人犹豫。

建议主行只留附件、输入和发送；当前资料保留一条简短状态。模型/思考强度/互动方式放同一设置入口，记住上次选择，需要时再改。不要靠增加说明文字解决选项太多。

### P2：书库默认优先可读性

书脊形式有辨识度，但长中文题目竖排/截断后不易寻找；“视图、排列、主题筛选、主题标题”又重复表达分组。

建议书架保留为可选视图，默认“最近阅读”的封面+横排标题列表；搜索旁只露“筛选”，高级排序收起。自己的书与示例经典要有明确区分。

### P2：统一设置入口语义

阅读器同时有“外观与回答”、全局设置和个人中心，主终端又有设置。用户难判断修改影响当前书还是整个账户。

建议阅读内只保留“阅读外观”和“笔记”，模型沿用全局并显示当前值；全局入口明确为“应用设置”。

### P2：清理日常列表中的验收项目

首页课程列表含“上传提速验收”“大 PDF 验收”等工程名称，和真实课程混排，放大了杂乱感。

建议提供归档/隐藏，默认只显示近期与收藏项目。本轮没有删除或改名任何已有课程。

### P2：减少大标题和重复装饰占用

阅读标题在桌面可占数行，空笔记本、书架装饰与大标题一起挤压正文。终端问候和故事卡也占据首次视线。

建议在工具页面限制标题高度、将状态缩为一行，给正文与当前任务更多空间；保持现有色彩与人物风格。

## 加载测量与限制

- 主入口静态 JS 闭包：2,207,618 → 616,954 字节，减少约 72%；逐文件 gzip 合计约 754 KB → 193 KB。
- 阅读外壳：原先先加载完整终端，实际父页面脚本约 3.85 MB；拆分后约 0.63 MB。这里不含 iframe 内阅读内容资源、字体、图片，不代表整站下载总量。
- 本机相同静态服务、相同账号夹具、相同 1440×1000 视口，模型目录统一人为延迟 1.2 秒：三次书库可见中位数约 1.772 → 0.770 秒，约减少 57%。此项验证“慢模型目录不再挡住书库”，不是生产 LCP、INP、低端真机或弱网结论。
- 发布前公网匿名抽测 `/`、`/api/me`、`/reader/` 首字节约 0.13–0.18 秒；认证用户、大文件、模型生成、腾讯验证码仍需分别衡量，不将其归因全部算作前端。
- 本轮未采集真实移动设备、VoiceOver/NVDA、完整 WCAG 合规或长期真实用户性能分位数。截图中的浅色文字与小按钮属于待实测风险，未给出无依据的对比度达标结论。
